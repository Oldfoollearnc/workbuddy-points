> 面向接手维护的人：一份文档说清"谁负责什么、数据怎么流、为什么这么切"。
> 界面迭代史见 `设计说明.md`，取数方案对比见 `本地数据源方案.md`。

## 1. 进程与窗口

单一进程（`desktop.py`），三个 WebView2 窗口 + 一个托盘：

| 窗口 | 标题 | 用途 | 生命周期 |
|---|---|---|---|
| 主窗 | `WorkBuddy 积分观测台 · 完整面板` | 四个页面 | 隐藏常驻，`--main` 时显示 |
| 小窗 | `WorkBuddy 积分观测台` | 右下角快捷面板 | 隐藏常驻，托盘单击切换 |
| 登录窗 | `WorkBuddy 账号登录` | 云端取数用的同源会话 | 仅扫码时显示 |

- 同一时刻只显示一个（`show_main()` 先隐藏小窗，反之亦然）。
- 关闭 = 隐藏到托盘；只有托盘菜单「退出」才 `quit()` 结束进程。
- 单实例互斥体 `Local\WorkBuddyPointsInsight`，避免两个进程抢 WebView2 数据目录。

**为什么用三个窗口**：pywebview 的 `js_api` 挂在窗口上，登录窗必须留在 `workbuddy.cn` 域内
才能带着会话调云端接口；把登录页塞进主窗会污染前端页面。

## 2. 线程模型

```
主线程            webview.start() → WinForms 消息循环
  ├─ 托盘线程      tray.py 自建消息窗口，收 WM_LBUTTONUP / 右键菜单
  ├─ usage 线程    UsageService.start() 扫描 JSONL（首次约 0.3–2s）
  ├─ 账号轮询      AccountService.start_polling() 每 30s 检查是否到期
  └─ 定时器        show/hide 后的布局校正、图标重设、minize 轮询
```

规则：
- 所有窗口操作走 `_safe_js()` / pywebview 线程安全封装，不直接 `Invoke`。
- 后台线程不碰 `webview.windows` 之外的 UI 状态；前端靠 `App.reloadUsage()` 拉取。
- `_watch_minimize` 只做一件事：检测 `IsIconic` → `SW_RESTORE` → 弹小窗。

## 3. 数据流

```
① 本机
   ~/.workbuddy/projects/**/*.jsonl
        │ usage_source._scan()   按 messageId 去重，取 rawUsage.credit
        ▼
   _aggregate() → daily / hourly / models / projects / ledger / insights
        │ 缓存 .cache/usage.json（按 mtime 签名失效）
        ▼
   js_api.get_usage() ─────────────┐
                                   ▼
② 云端                        assets/js/app.js
   POST /billing/meter/…           │  normalize() → D
   POST /billing/meter/get-user-request-usage
        │ account_service._map()   │  ACCOUNT
        ▼                          ▼
   account.json 缓存          renderActive() → renderOverview / Analytics / Ledger / Settings
```

**合并规则（重要）**

| 视图 | 取值顺序 |
|---|---|
| KPI 余额 / 周期 / 有效期 | 云端 → 本机配置（`points_config.json`，仅兼容旧数据） |
| 今日消耗 / 调用 / Token | 本机（实时）；Token 只来自本机 |
| 消耗日历 | 云端逐笔 → 本机补盲区；Token 有本机同日记录才给值 |
| 模型使用量 | 云端 `cloudModels`（近 30 天）→ 本机 `models30` |
| 积分流水 | 云端 `usageRows` → 本机 `D.ledger` |
| 项目排行 | 只用本机（云端无 cwd） |

每个视图的 **来源 chip / 副标题** 必须与上表一致，不允许"数据是云端的、文案写本机"。

## 4. 前端结构（app.js）

```
boot()
 ├─ bind()                 一次性事件绑定（不重复注册）
 ├─ loadUsage()/loadAccount()/loadVersion()
 └─ bootRender() → renderActive()
renderActive(force)         250ms 节流；按 state.view 分发
 ├─ renderOverview()       KPI / 洞察条 / 时段柱 / 额度仪表 / 趋势 / 构成环
 ├─ renderAnalytics()      日历 / 模型行 / 项目行 / 洞察
 ├─ renderLedger()         汇总 / 分组（按分钟）/ 加载更多
 ├─ renderSettings()       外观 / 行为 / 数据源 / 关于
 └─ renderPopup()          小窗（今日使用积分 / 环图 / 时段柱）
```

约定：
- **卡片内不做 DOM 复用**：每次整块 `innerHTML`，避免状态错位；图表容器走 `Charts.mount()` 清空。
- **不用 ResizeObserver**：窗口 resize 统一 180ms 去抖后 `renderActive()`，避免"绘制→尺寸变化→再绘制"的反馈循环。
- **主题**：所有颜色来自 CSS 变量；切主题后 60–90ms 重绘图表（`:root` 变量已是新值）。
- **数字格式**：`F.credit()` 统一（≥1000 不显示小数），避免"1,234.56"撑破容器。

## 5. 窗口自绘（为什么不用系统标题栏）

- 系统标题栏会和页面标题重复，且无法跟随深色主题（Win10 的标题栏底色不可控）。
- 因此主窗 `frameless=True`，顶栏自己画：拖动、双击最大化、三个窗口按钮、缩放手柄。
- **踩坑**：给无边框窗口补 `WS_THICKFRAME` 来恢复拖边缩放，会带来 8px 非客户区
  （深色下是一条近黑色带，即"顶部黑边"）。现在改为纯客户区 + 前端 8 向缩放手柄，
  `win_resize(x,y,w,h)` 直接给新矩形。
- **踩坑**：pywebview 自带的 `pywebview-drag-region` 用 `screenX - clientX` 当增量，
  窗口一移动坐标就被重算，越拖越快（实测 60px 鼠标位移跑出 200px）。
  改为自己算绝对位置（`win_pos()` + `win_move()`，12ms 节流）。

## 6. 版本号

```
.githooks/pre-commit   →  读取 version.json，修订号 +1，git add
desktop.read_version() →  js_api.get_version()  →  顶栏 / 设置-关于 / 窗口标题
```
仓库内执行一次 `git config core.hooksPath .githooks` 即可对所有克隆生效。

## 7. 打包

```
build.spec        PyInstaller onedir（onedir 启动快、杀软误报少）
  ├─ datas: index.html / assets / version.json / webview 静态资源
  ├─ collect_all: webview, pythonnet, clr_loader（.NET 互操作 DLL）
  └─ console=False（托盘程序，不弹黑框）

installer/*.iss   Inno Setup：Program Files + 快捷方式 + WebView2 检测 + 卸载
```
运行时路径：资源随 exe 走（`app_paths.bundle_dir()`），
可写数据写 `%APPDATA%\WorkBuddyPoints`（`app_paths.data_dir()`）。
