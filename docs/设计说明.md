# WorkBuddy 积分观测台
## 界面设计与实现说明（Windows 桌面端 · 真实数据版）

> 观测对象：本机 WorkBuddy 账号的真实积分消耗
> 形态：托盘常驻 → 右下角快捷面板 → 全尺寸主界面
> 技术栈：WebView2（pywebview 6）+ 原生 Win32 托盘 + 手写 SVG 图表（零第三方图表库）

---

## 1. 数据从哪来（真实数据链路）

应用不编造任何数字，全部来自 WorkBuddy 在本机写下的运行记录：

| 步骤 | 位置 | 内容 |
|---|---|---|
| ① 读取 | `%USERPROFILE%\.workbuddy\projects\<项目>\<会话>.jsonl` | 每次模型调用的原始记录 |
| ② 提取 | `providerData.rawUsage.credit` | 该次调用真实扣除的积分（小数） |
| ③ 伴随字段 | `providerData.model` / `usage.totalTokens` / `timestamp` / `cwd` / `name` | 模型、Token、时间、项目、工具名 |
| ④ 聚合 | `usage_source.py` | 按日 / 小时 / 项目 / 调用类型汇总，写入 `.cache/usage.json` 缓存 |
| ⑤ 传输 | `js_api.get_usage()` | Python 聚合结果直接交给前端渲染 |

去重：同一次调用会在多个记录里出现，按 `providerData.messageId` 去重，保证不重复计费。

**余额说明（重要）**：本机记录只有"消耗"，没有账户剩余额度。因此：

- 未配置额度时，KPI 显示"本周期消耗"，进度条为 0，不虚构余额；
- 在「设置 → 账号与额度」填写总额度与周期起止后，`可用余额 = 总额度 − 周期内累计消耗`，同时显示已用比例与预计耗尽日；
- 配置保存在 `points_config.json`，不联网、不上传。

数据只读、只在本机解析，不发起任何网络请求。

## 4. 图表规格（全部来自真实记录）

| # | 图表 | 类型 | 数据维度 | 标注 | 交互 |
|---|---|---|---|---|---|
| 1 | 今日消耗时段分布 | 24 柱 | 小时 × 积分，附该小时调用次数 | 柱顶数值 + 左轴刻度 + 峰值 chip + 当前时段虚线 | 悬停显示时段、积分、占比 |
| 2 | 今日消耗构成 | 环形图 | 模型 × 积分（计费主体，归因精确） | 环上百分比（≥12%）+ 图例（名称/积分/占比）+ 中心合计 | 悬停高亮扇区并联动图例 |
| 3 | 近 N 天消耗趋势 | 柱 + 折线（双轴） | 日期 × 每日消耗（柱）、区间累计（线） | 左轴消耗、右轴累计、每 5 日刻度 | 悬停显示当日消耗与累计；可切 7/14/30 天 |
| 4 | 额度与消耗 | 仪表盘 220° | 本周期已用比例 | 中心百分比 + 周期剩余天数；未配置时显示"未设置额度" | 下方指标：总额度、近 7 日均、预计耗尽日 |
| 5 | 近 7 天模型消耗堆叠 | 堆叠柱 | 日期 × 模型（Top5） | 柱顶当日合计 + 底部图例 | 悬停逐行列出各类型积分与占比 |
| 6 | 项目消耗构成 | 环形图 | 近 7 天项目（Top5 + 其他项目） | 环上百分比 + 明细图例 | 悬停高亮 |
| 7 | 项目 × 时段热力 | 热力矩阵 | 项目（cwd）× 小时 × 积分 | 颜色深浅 + 色阶图例 | 悬停单元格放大并显示明细 |
| 8 | 项目消耗排行 | 横向条形 | 近 7 天 Top6 项目 | 条形长度 + 右侧积分与占比 | 悬停显示消耗占比 |
| 9 | KPI 迷你趋势 | Sparkline | 近 14 天余额/消耗 | 无轴，仅趋势 | 无 |

**关于准确性**（重要）：

| 维度 | 来源 | 准确度 |
|---|---|---|
| 积分总额 / 每日 / 每小时 | `rawUsage.credit` 逐次累加 | 精确（WorkBuddy 自己扣的数） |
| 模型 | `providerData.model` | 精确（该次调用就是由它计费） |
| 项目 | `cwd` | 精确（该次调用发生在该项目） |
| Token | `usage.totalTokens` | 精确，但口径是"上下文累计"，不等于去重后的字数 |
| 调用动作（命令执行/文件写入…） | 记录里的工具名归并 | **启发式**：一次调用的积分属于这次模型调用，工具只是它当时的动作，不能算严格分摊 |

因此主视觉维度使用**模型 / 项目 / 时段**，这三者能对上每一笔积分；"动作"只在流水里作为描述性信息展示，不参与构成统计。单一模型时环图会是一个整环，此时卡片底部补一行真实统计（调用次数、平均每次积分、累计 Token）避免信息量过低。

**口径一致性**：环形、柱状、堆叠、流水全部来自同一份聚合结果，任意两个视图的合计可对上。

## 6. 主题切换

1. 全部颜色来自 `data-theme` 下的 CSS 变量，组件零硬编码色值。
2. 切换时以按钮为圆心做 `clip-path: circle()` 波纹（560ms），240ms 时切换主题，再淡出蒙层。
3. 切换后 60ms 重绘图表（读取新变量），避免"深色底 + 浅色旧图"。
4. 双窗口同步：`localStorage` + `sync_theme()` 双通道。
5. 支持"跟随系统"，偏好持久化。

## 7. 动效

统一 `cubic-bezier(.16,1,.3,1)`，只动 `transform / opacity / box-shadow`。

| 场景 | 实现 | 时长 |
|---|---|---|
| 页面切换 / 卡片入场 | CSS keyframes + 阶梯延迟 | 300 / 420ms |
| 图表柱体、环形、折线 | rAF 逐帧（浏览器预览） | 760–900ms |
| 数值 | 直接落地（见下） | — |
| 悬停 / 按压 | CSS transition，`scale(.97)` | 140–220ms |
| 主题波纹 | clip-path 圆扩散 | 560ms |
| Toast | 位移 + 缩放 | 260ms |
| 刷新 | 内容降透明 + 顶部扫光 | 560ms |

**一个必须说明的取舍**：WebView2 在窗口被遮挡或未激活时会挂起渲染线程，rAF 与定时器都不推进。若依赖 rAF 做图表/数字入场，画面会永久停在首帧（本机实测显示为 0 或空白）。因此桌面壳内**图表直接呈现终态、数值直接写入**，入场动效交给 CSS（合成层动画不受影响）；浏览器预览仍保留完整的逐帧动效。代价是没有"数字滚动"，收益是任何窗口状态下数据都不会显示错误。

## 8. 交互

- 托盘单击切换面板；右键菜单：快捷查看 / 展开主界面 / 刷新 / 退出；首次启动弹气泡提示。
- `Esc` 收起小窗，`Ctrl+R` 重新读取本机记录，`Alt+1..4` 切换页面。
- 刷新会重新扫描 JSONL（有 mtime 缓存，通常 < 0.3s），完成后 Toast 提示。
- 搜索 140ms 防抖；流水支持"全部/今日/近 7 天"；加载更多按 24 条递增。
- 失败可见：启动异常写 `logs/app.log` 并弹对话框；重复启动提示已在运行。

## 10. 性能与资源（实测）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 空闲 CPU | 30–50%（持续） | 0–3% |
| 内存 | 持续增长（消息队列堆积） | 稳定，无增长 |
| 交互 | 面板持续闪烁、主界面卡死、鼠标被抢占 | 稳定，无闪烁 |

三个根因：

1. **主题同步死循环**：窗口 A 切换主题后经 Python 通知窗口 B，B 又反向通知 A，形成 IPC 洪泛，UI 线程被打满。现在只有"主动切换"才广播，被动接收方不再回推，并加了同值短路。
2. **大面积毛玻璃**：侧栏与顶栏的 `backdrop-filter: blur(18px)` 在无独立显卡的机器上会逐帧重算，静态也吃 30% CPU。已改为高不透明度纯色底。
3. **尺寸反馈循环**：图表容器上的 `ResizeObserver` 在绘制引起尺寸微变时会反复触发。已移除，改由窗口 resize（180ms 去抖）+ 显式渲染驱动。

另外：默认对 WebView2 关闭 GPU 合成（`--disable-gpu`），本机无独显时更稳；渲染节流 250ms，任何重复渲染请求直接丢弃；小窗打开后只做一次布局校正。

资源占用：WebView2 双窗口约 500MB（python 100MB + 两个渲染进程 + 共享浏览器进程），这是 WebView2 的固有开销，不是泄漏——长时间运行内存不增长。

## 11. 拷贝给别人能用吗

可以。程序不含任何账号密钥，数据来自**运行它的那台电脑**上的 `~/.workbuddy`：

- 同事拿到后运行，看到的是**他自己**的积分消耗；
- 如果他那台机器上没有 WorkBuddy 使用记录，界面会显示"今日暂无消耗"并提示"本机记录中还没有积分消耗"，不会出现假数据；
- 额度配置保存在程序目录的 `points_config.json`，各人各自填写。

## 12. 界面改造记录（2026-10-21 晚）

### 主题切换
放弃"整页遮罩从按钮扩散"的写法（大范围覆盖有明显遮挡感），改为 **View Transitions 交叉淡入**（260ms，旧层轻微放大 1.006、新层从 0.994 回正）。不支持该 API 时直接切换，不做降级遮罩。

### 设置页
- 结构改为两行栅格：`外观`（主题三卡 + 动效三档 + 两个开关）｜`账号`（头像/昵称/套餐/手机号 + 四项云端指标 + 积分包进度 + 连接操作）；
  第二行 `数据源`（云端/本地记录/覆盖天数/同步间隔）｜`快捷面板`（预览小窗 + 版本）。
- **删除**「账号与额度」手动填额度板块：余额与周期已由云端提供，不再需要手工配置。
- 卡片改为顶部对齐，不再随相邻卡片拉伸。

### 顶部 Dock
从左到右：**同步状态（绿点 + 时间，可点击立即同步）** → 刷新（只读本地）→ 主题 → 收起为小窗 → 账号头像。

- 头像优先用云端 `avatarUrl`（COS 签名图），失败回退昵称首字；tooltip 显示 `昵称 · 套餐 · 手机号`。
- 「收起为小窗」与系统最小化**不重复**：最小化进任务栏，收起是把主窗隐藏并在右下角弹出 424×656 的常驻面板。为避免误解，按钮改为纯图标并在 tooltip 说明，文案只保留在悬停提示里。

### 图表
- **环形图**：段间重叠 0.6px 消除抗锯齿白缝，整环视觉闭合；百分比标注统一——≥7% 标在环内，<7% 用引线标到环外，保证每一项都有占比。
- **消耗日历**：替换原「近 7 天模型堆叠」，GitHub 贡献图样式（12 周 × 7 天），颜色按当日消耗分位分 5 档，悬停显示日期/消耗/调用次数。数据**优先云端**（billing 逐笔汇总），未连接时用本地记录并显示「本地估算」黄色标记。
- **流水**：同一分钟的记录合并展示（首条显示时间 + `×N` 徽标，其余用左侧导轨承接），仍按时间倒序。刷新按钮**只读本地**，云端同步走定时任务或「立即同步」，避免频繁请求触发风控。

### 任务栏图标
`SetCurrentProcessExplicitAppUserModelID("WorkBuddy.Points.Insight")` 让窗口按应用分组，再用 `WM_SETICON`（32/16）设置 `assets/icon.ico`，替换默认的 python.exe 图标。

## 13. 第三轮迭代（2026-10-21 深夜）

### 窗口行为
- **最小化 = 收起为右下角小窗**：轮询 `IsIconic`，检测到最小化立即 `SW_RESTORE` 并弹出小窗，不再进任务栏。
- **主窗与小窗互斥**：`show_popup()` 先隐藏主窗，`show_main()` 先隐藏小窗。
- Dock 删除「收起」按钮（与最小化重复）；头像点击进入设置页；侧栏品牌块与左下角主题开关删除（与右上角重复）。

### 额度算法（核心新增）
```
可用积分  = 云端 TotalCredits
周期终点  = 最早到期的积分包 (CycleEndTime)
剩余工作日 = [今天, 周期终点] 内剔除周末与法定节假日
签到补偿  = 100 × 剩余天数（可在设置关闭）
每日可用  = (可用积分 + 签到补偿) ÷ 剩余工作日
本周可用  = 每日可用 × min(5, 剩余工作日)
```
节假日表内置在 `assets/js/holidays.js`（2025–2027），可在设置里关闭"工作日折算"改为按天平均。
设置页新增：工作日折算、计入签到、本地刷新间隔（30s/1min/5min/手动）。

### 图表
- 今日消耗构成：环形图 → **横向堆叠条 + 明细列表**（单一模型时不再是一个大饼）。
- 消耗日历：卡片整行铺满，格子 16px、最多 30 周；移除逐格 `transition` 与 hover 描边，鼠标快速划过不再反复重绘。
- 项目消耗构成 → **模型使用量**（排名 + 占比条 + 积分/占比）。
- 移除与日历重叠的「项目 × 时段热力」。
- 流水「×N」改为「×N · 累计积分」，语义从"条数"改为"该分钟合计"。

### 小窗
去掉环形图、时段柱、搜索框；改为「可用积分 + 额度进度 + 一条构成比例条 + 最近 3 条」。

## 14. 第四轮迭代（2026-10-21 深夜 · 窗口自绘与空间利用）

> 本轮目标：去掉系统标题栏、把每张卡片的空白用真实数据填满、修复主题切换失效，
> 并在不改动云端请求频率的前提下让云端逐笔真正生效。界面效果见 `docs/screenshots/`。

### 14.1 窗口（A）

| 项 | 做法 |
|---|---|
| 主窗无边框 | `frameless=True` + `shadow=False`；顶栏即标题栏（页面标题 + 拖拽区 + Dock + 三个窗口按钮） |
| 窗口按钮 | 自绘 `#winMin / #winMax / #winClose`，46×64 命中区，颜色全部走 `--text-2 / --surface-3`，深浅色都跟随；关闭键 hover 为 `#e81123` |
| 拖动 | 自己实现：`win_pos()` 取窗口原点，`mousemove` 用**绝对坐标** `win_move(x,y)`（12ms 节流）。**不用** `pywebview-drag-region`——它把 `screenX - clientX` 当增量，窗口移动后坐标被重算，越拖越快（实测 60px 鼠标位移会跑出 200px） |
| 双击 | 顶栏 `dblclick`（排除按钮）→ `win_max()` |
| 最大化 | 手工 `SetWindowPos` 到工作区（不盖任务栏），记住原矩形；图标在 `#i-max / #i-restore` 间切换，`body.is-maximized` 同步 |
| 最小化 | `SW_MINIMIZE` → 既有 `IsIconic` 轮询立刻 `SW_RESTORE` 并弹出右下角小窗（不进任务栏） |
| 关闭 | 按设置 `close_to_tray` 隐藏到托盘；关掉该开关才退出进程 |
| 边缘缩放 | 给无边框窗口补 `WS_THICKFRAME`，恢复系统边缘拖拽缩放（7px 细边） |
| 任务栏图标 | 根因：`SetCurrentProcessExplicitAppUserModelID` 在 **shell32**，此前写在 kernel32 上静默失败 → 任务栏一直用 python.exe 的图标。改为 shell32 调用 + `webview.start(icon=icon.ico)` + `WM_SETICON` |

### 14.2 总览（B）

- **今日消耗构成**：改为 `环形图（占比 + 圆心合计） + 堆叠条 + 明细列表` 三段式，环图尺寸随卡片高度自适应（最高 260px），不再是一条横条 + 一行字。
- **额度与消耗**：保留本周可用 / 周期剩余 / 每日可用，新增「今日用量 / 日均额」进度条（刻度线标在 100% 日均额处）与一句话结论：
  - 未超：`今日还可消耗 X 分` + `再消耗 Y 分（日均额的 10%）后仍占日均 N%`
  - 已超：`今日已超出日均 X 分` + `若再消耗 Y 分将超出当日均额 P%`
  - `Y = 日均额 × 10%`：单次调用往往只有零点几分，用"一次调用"做假设会让百分比失去意义。

### 14.3 用量分析（C）

- **日历铺满**：列数由容器宽度与高度共同决定（`目标列数 = 可用宽 ÷ (格高×1.26 + 间隙)`），列宽再回填剩余宽度，**左右严格贴边**；窗口放大时列数与格子同步变大（1408 → 约 26 列，1920 → 约 37 列，3440 上限 52 列）。
- **整月对齐**：起点固定为「某月 1 号所在周的周一」，在最近 12 个月里挑列数最接近目标的那个月；1 号之前的日子不画格子，视觉上明确"从这个月开始"。不再从随机日期起步。
- **tooltip 四项**：日期（含星期/未到/来源）、消耗积分、消耗 Token、调用次数。云端逐笔不含 Token → 有本机同日记录用本机 Token，没有就显示 `—`，绝不估算。
- **来源标记**：`云端 + 本机` / `云端逐笔` / `本地记录` / `暂无数据`，鼠标悬停有口径说明。
- **单模型**：模型卡片在只有 1 个模型时切换为「占比环（100%）+ 明细（模型/调用次数/平均每次/累计 Token）+ 说明」，不再是孤零零一行。
- **左右对齐**：模型使用量与项目消耗排行改用同一套 `.rows-head / .rows-row` 栅格（18px 序号 · 名称 · 占比条 · 78px 积分 · 54px 占比），行高 42px、内边距一致，两边行号与基线严格对齐。

### 14.7 主题切换失效 · 根因

`app.js` 的 `paintTheme()` 首行读 `lastPainted`，而该变量**从未声明**。文件整体包在 `(function(){ 'use strict'; … })()` 里，读取未声明标识符直接抛 `ReferenceError`，函数第一行就中断 → `data-theme` 永远不变，图表自然也不重绘。与 View Transitions 无关。

修复与加固：

1. 补 `let lastPainted = null`；
2. 主题落地加 60ms **看门狗**：View Transitions 的回调要等下一帧，而 WebView2 关闭 GPU 合成/窗口未聚焦时可能长时间不产帧，回调不执行就会表现为"点了没反应"；现在无论过渡是否真的开始，主题都会立即生效；
3. `paintTheme` 之后固定 90ms 重绘图表（颜色全部读 CSS 变量）；
4. 保留 260ms 交叉淡入（`::view-transition-old/new(root)`），不做全屏遮罩。

实测：点击后 **12ms** 内 `document.documentElement.dataset.theme` 变为目标值，`getComputedStyle` 背景色与图表 `stop-color` 同步切到新色板，无控制台异常。

### 14.8 云端逐笔为空 · 结论

`get-user-request-usage` 本身可用（本次实测 `daily=4`、30 天 216 条），历史"daily=0"是旧版只取第 1 页且未做分页循环导致的；现已按 `total` 翻页（≤5 页）。本轮把云端逐笔提升为**日历与模型用量的首选口径**，并在 `_map()` 里新增 `cloudModels`（近 30 天每模型积分 + 调用次数），缓存进 `account.json`。

云端响应**不含 Token 字段**（`requestId/credit/model/client/requestTime/agentPurpose/appType`），因此 Token 一律标注来源或显示 `—`。
