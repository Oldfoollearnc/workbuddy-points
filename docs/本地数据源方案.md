# 本地数据源方案（公司电脑怎么读到本机数据库）

> 结论先说：**三级定位 + 快照读取**。
> 手动指定 > 环境变量 > 自动探测；数据库一律"先复制再读"，不与客户端抢锁。

---

## 一、问题是什么

个人电脑上数据固定落在 `%USERPROFILE%\.workbuddy`，公司电脑至少三种偏差：

| 现象 | 原因 |
|---|---|
| 程序显示"未找到本机记录" | 域账号的 `%USERPROFILE%` 被重定向到网络盘，或客户端把数据放到了 `%APPDATA%` / `%LOCALAPPDATA%` |
| 读到一半报错 / 数据偏少 | `workbuddy.db` 被客户端以 WAL 模式独占，直接 `sqlite3.connect` 会 `database is locked`，或读到未 checkpoint 的旧页 |
| 换机/重装后没有历史 | 本地记录本来就只属于那台机器，不做跨机同步（见 README 第 1 节） |

---

## 二、选定方案

### 1. 目录定位：三级优先级

```
① 设置里手动选择（datasource.json: {"home": "..."}）
       ↓ 未配置或无效
② 环境变量 WORKBUDDY_HOME
       ↓ 未配置或无效
③ 自动探测（逐个校验结构）：
   %USERPROFILE%\.workbuddy
   %APPDATA%\WorkBuddy
   %LOCALAPPDATA%\WorkBuddy
   %USERPROFILE%\.codebuddy
   D:\WorkBuddyData
       ↓ 全不命中
④ 回退默认路径，界面标记 invalid + 「选择目录」引导
```

"有效"的判定：目录里存在 `projects/`（会话 JSONL）或 `workbuddy.db` 之一。
命中后 `data_source.resolve()` 返回来源标签（手动/环境变量/自动），设置页直接显示
**为什么是这个路径**，而不是只给一个失败提示。

### 2. 数据库读取：先快照再读

```python
_snapshot_db(db)   # 连同 -wal / -shm 复制到临时目录
sqlite3.connect("file:<tmp>?mode=ro", uri=True)
```

- 不与客户端抢文件锁；
- WAL 里已提交但未 checkpoint 的数据也能读到；
- 代价：每次多一次几百 KB 的拷贝（本机 230KB，毫秒级）。

### 3. 数据兜底顺序

```
JSONL 明细存在  → 逐笔/模型/项目/Token 全量（精确）
JSONL 缺失      → workbuddy.db 的 session_usage 汇总（仅日级，界面标注"数据库估算"）
两者都没有      → 空态 + 「选择目录」引导，不编造数据
```

`session_usage.credit_json` 是 `{requestId: credit}`，只能算出"每个会话用了多少"，
没有逐笔时间和模型，所以 DB 兜底只用于"看不到明细时至少知道每天大概用了多少"。

## 三、取舍

| 方案 | 优点 | 缺点 | 是否采用 |
|---|---|---|---|
| **A. 手动指定目录** | 确定性强，任何重定向都能解决；一次设置长期有效 | 需要用户点一次（设置页 → 数据源 → 选择目录） | ✅ 第一优先 |
| **B. 环境变量 `WORKBUDDY_HOME`** | IT 可用组策略批量下发，用户零操作 | 需要管理员配置；改完要重启程序 | ✅ 第二优先 |
| **C. 自动探测候选目录** | 零配置，覆盖常见安装形态 | 只能覆盖"常见"路径，遇到自定义盘符就失效；多份数据时可能选错（按固定优先级取第一个） | ✅ 兜底 |
| D. 让用户手工导入 JSON/CSV | 完全不依赖路径 | 每次都要操作，且导出格式不稳定 | ❌ 仅作为最后手段在文档里提 |
| E. 读客户端 Cookies 直连 | 不用登录 | 边界模糊（读别的程序的凭证），客户端加密升级即失效 | ❌ 不做 |
| F. 把本地数据上传云端做跨机同步 | 真正跨设备 | 需要后端与账号体系；逐笔重复上传有计费口径风险；公司合规通常不允许 | ❌ 不做 |

**为什么不是"只做自动探测"**：公司电脑的路径千奇百怪，一旦探测失败，用户只会看到
"没有数据"，没有任何自救手段。手动指定是唯一 100% 可控的兜底，且成本只有一次点击。

**为什么不是"直接读库、不做快照"**：实测客户端运行时 `workbuddy.db` 被独占，
不复制就会抛 `database is locked`；复制还能顺带解决 WAL 未落盘的问题。

## 四、实现位置

| 文件 | 职责 |
|---|---|
| `data_source.py` | `resolve()` 三级定位、`set_home()/clear_home()`、`db_summary()` 快照读取 |
| `usage_source.py` | 用 `resolve()` 的结果扫 JSONL；无记录时用 `db_summary()` 兜底 |
| `desktop.py` | `get_datasource / choose_data_dir / reset_data_dir` 三个 js_api |
| `app.js` | 设置页「数据源」分组：显示路径、来源、结构、按钮 |

配置存放：`%APPDATA%\WorkBuddyPoints\datasource.json`（开发态在项目目录）。
